# ADMIN UI STYLE GUIDE

이 문서는 `그누5어드민`의 관리자 UI 시각 언어와 레이아웃 기준을 고정하는 지원 문서다.
실제 작업 상태는 `specs/TODO.md`, 구현 완료 이력은 `specs/HISTORY.md`를 기준으로 본다.

## 1. 사용자

- 웹에이전시 실무 운영자
- 프리랜서 구축/유지보수 담당자
- 쇼핑몰 운영자

핵심 전제는 `랜딩 페이지 사용자`가 아니라 `반복 작업을 빠르게 처리해야 하는 관리자`다.

## 2. 목표 인상

- 웹사이트보다 `데스크톱 관리자 앱`처럼 보여야 한다.
- 전형적인 admin template 계열의 구조감과 안정감을 우선한다.
- 시각적 포인트보다 `정렬`, `구조`, `밀도`, `작업 속도`를 우선한다.

## 3. 레이아웃 기준

- 상단은 `고정 최상위 탭 + 열린 사이트 탭` 기준으로 고정한다.
- 로그인 전 절차 화면은 `단일 컬럼 entry screen`으로 통일하고, 표시 설정 툴바/상단 작업 탭을 노출하지 않는다.
- 열린 사이트 탭은 현재 활성 사이트를 우선 노출하고, 나머지는 등록 순서를 유지한다.
- 등록 사이트 전체를 탭에 모두 노출하지 않는다. 탭에는 `최근/열린 사이트`만 올리고, 나머지는 `더보기` 메뉴에서 연다.
- 좌측은 `현재 상단 탭의 서브메뉴`만 고정한다.
- 중앙은 현재 작업면만 보여준다.
- 멀티사이트 UX는 `상단 작업 탭 + 좌측 서브메뉴 + 중앙 작업면`이 canonical 이다.
- `/overview`만 안내형 hero를 허용하고, 일반 관리자 화면은 compact header를 기본으로 한다.

## 4. 시각 언어

- 카드와 패널은 `플랫하고 단단한` 표면을 기본으로 한다.
- 전체 배경은 `#efefef` 계열 neutral surface, 그 위 카드/폼/작업 박스는 흰색 표면을 기본으로 한다.
- 큰 라운드, 둥글둥글한 모바일 앱 느낌은 금지한다.
- 과한 그림자, 과한 유리 효과, 과한 그라디언트는 금지한다.
- 여백은 답답하지 않을 정도로만 두고, 구조를 흐릴 정도의 큰 공백은 피한다.
- 메뉴 아이콘, 배지, 버튼은 간격과 baseline이 일정해야 한다.
- 설명 문구는 짧고, 한 문단이 길어지지 않게 한다.

## 5. 컴포넌트 밀도

- 상단 컨트롤, 서브메뉴, 카드 헤더는 compact rhythm을 유지한다.
- 버튼/입력/배지/아이콘 박스는 큰 pill보다 `작고 정렬된 rectangle` 톤을 우선한다.
- 숫자 KPI 카드, 최근 작업, 빠른 링크는 `한 화면에서 구조가 바로 읽히는 밀도`를 유지한다.
- 테이블 헤더는 작은 uppercase 라벨과 촘촘한 행 높이를 기본으로 한다.
- 검색/필터/폼 입력은 `둥근 웹 폼`보다 `작업 도구용 control bar` 느낌을 우선한다.
- 설명은 input처럼 보이면 안 된다. 설명 블록은 info icon/callout 계열로 입력 영역과 시각적으로 분리한다.
- 긴 편집 화면은 좌측 서브메뉴를 sticky로 유지하고, 저장 액션은 상단과 하단에 모두 둔다.

## 6. 금지사항

- 과한 여백
- 과한 shadow
- 큰 radius
- 감성형 hero 남발
- 마케팅 사이트 같은 카드/배너 위주 구성
- 지원하지 않는 기능을 비활성 input/card처럼 애매하게 노출하는 것

hero는 메인 화면(`/overview`)에서만 제한적으로 허용한다.

## 7. 로딩 UX

- 로딩은 가능한 빠르게 보여야 한다.
- 즉시 완료되지 않는 경우 skeleton, placeholder, spinner 중 하나로 `지금 로딩 중`임을 명확히 드러낸다.
- 빈 화면이나 정지된 화면처럼 보이는 상태를 만들지 않는다.

## 8. 테마 방향

- 표시 설정 툴바는 현재 해석된 테마를 보여주는 `단일 토글 버튼`을 제공한다.
- 앱 내부 테마 모델은 `light / dark / system`을 유지하고, `system`은 현재 OS `prefers-color-scheme`를 따라간다.
- 테마 선택은 로컬 저장소에 기억되고, 루트 dataset에도 반영돼 screenshot/test/manual verify에서 같은 상태를 재현할 수 있어야 한다.
- 테마 전환 버튼은 pill보다 `작은 rectangle toggle` 톤을 우선한다.

## 9. 현재 디자인 판단 체크리스트

아래 질문에 `예`가 많아야 현재 방향에 맞는다.

- 상단 작업 탭과 좌측 서브메뉴 구조가 한눈에 읽히는가?
- 사이트 탭이 현재 작업중인 사이트만 보여주고, 과도한 등록 사이트는 `더보기`로 빠지는가?
- 소개 문구가 짧고 바로 작업으로 이어지는가?
- 화면이 웹사이트보다 관리자 툴처럼 보이는가?
- 메뉴/아이콘/배지가 일정한 간격과 크기 리듬을 가지는가?
- radius와 shadow가 눈에 띄지 않고 구조만 보이게 돕는가?
- overview 외 화면에서 hero/배너가 과하게 튀지 않는가?
- 로딩 상태가 빈 화면 없이 명확하게 표현되는가?
- 표시 설정 툴바가 현재 라이트/다크 상태를 한 번에 토글 가능하게 보여주는가?
- 작업면 카드, 표, 검색 bar, 액션 타일이 셸과 같은 compact admin template 밀도를 유지하는가?
- 설명 영역과 입력 영역이 한눈에 구분되는가?
- 지원하지 않는 기능이 일반 모드에서 과하게 보이지 않는가?
